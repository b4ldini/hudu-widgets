Before you start
Prerequisites for every migration engagement
Always run destructive scripts in preview mode first. PnP.PowerShell requires PowerShell 7 and an Entra app registration for interactive login.
  • PowerShell 7 installed and PnP.PowerShell module available.
  • Entra app registration in place with the required Graph and SharePoint API permissions.
  • Customer sign-off on the folder structure and destination SharePoint site obtained before Phase 1.
  • Antivirus exclusion for E:\ (or the source drive) confirmed on the Migration Manager agent box.
  • Out-of-hours change window agreed if the file server is in active daily use.

0 of 10 phases complete
P0 Discovery & Remediation Establish a clean baseline
  • Scan the source for size, file/folder counts, and residual issues (zero-byte files, illegal characters, long paths). Lock a baseline. Phase0-Scan.ps1
  • Quarantine junk (Thumbs.db, desktop.ini, temp files); park long-path and suspected-backup files separately for later review.
  • Record anything moved or quarantined for customer notification before Phase 1 sign-off.
P1 Target Preparation Destination ready and unambiguous
  • Create or confirm the SharePoint site and document library. Agree the destination folder structure with the customer, mirroring the source.
  • Set versioning on the library (major versions only is typical; discuss with customer).
Confirm the real library. The default library is internally named Shared Documents even when displayed as "Documents". Watch for redundant empty libraries and bind migration tasks to the correct one.
P2 Migration Move the data reliably
  • Use Microsoft Migration Manager — agent on the file server, cloud-orchestrated, so it survives RMM/session logout. Avoid session-tied tools.
  • Exclude E:\ (source drive) from antivirus on the agent box to prevent file-lock loops during transfer.
  • Add tasks via bulk CSV — one task per subfolder. Settings: replace invalid chars → _; exclude hidden files; Entra ID lookup ON; date/extension filters OFF.
Bind tasks to the existing library plus a subfolder — never the library root. Binding to the root attempts to create a list and will fail.
P3 Reconciliation Prove every file arrived
  • Compare visible (non-hidden) file counts per folder, source vs SharePoint. Reconcile-Fast.ps1 is paged and timeout-proof.
  • For any shortfall, list the exact missing files by name. Find-MissingFiles.ps1
Raw counts mislead because hidden files are excluded by design. Always reconcile on visible counts, not totals from Explorer or the Migration Manager summary.
P4 Remediation of Misses Resolve genuine gaps
Issue Resolution
Long paths Windows MAX_PATH (260) and SharePoint (~400) are different limits. Shorten parent folder names; use the \\?\ prefix to reach files Explorer can't open.
Reserved names & emoji Reserved names ("Forms") and emoji in filenames must be renamed at source before re-running the migration task.
Root files / coverage gaps Per-subfolder tasks miss loose files in a folder root — add a dedicated task for that folder root, or upload manually.
Junk / hidden items Confirm items like .git internals and hidden folders are excluded by design, not genuinely lost.
P5 Final Delta Sync Catch last-minute changes before cutover
  • Scan files changed or created during the cutover window. Final-DeltaSync.ps1
  • Re-run the affected Migration Manager tasks (incremental mode), then verify each changed file replicated with its new version using -Verify.
P6 Security Model Folder-level access via groups
  • Read source NTFS permissions; expand groups to individual people. Get-FolderPermissions.ps1
  • If the tenant is not AD-synced, match users to Entra by display name against an export of licensed users — never trust username or UPN consistency. Keep only enabled, SharePoint-licensed users; flag the rest for manual review.
  • Create SP_<FOLDER>_RW (Edit) and SP_<FOLDER>_RO (Read) security groups in Entra. Grant each on its folder via Set-PnPListItemPermission by list-item ID — this breaks inheritance on that folder.
  • Add members with Add-GroupMembers.ps1.
  • Add a view-only verification group so the customer can spot-check content access before go-live.
Deactivate the "Limited-access user permission lockdown mode" site feature — required for folder-level sharing to work. Allow 15–60 minutes for new security groups to become usable in SharePoint after creation.
P7 Offboarding Leavers Remove departed staff cleanly

Per leaver: block sign-in → archive mailbox (convert to Shared — retains mail, no licence required) → remove all licences. Decommission-Users.ps1

Unlicensed users are auto-excluded from SharePoint access groups — no manual group cleanup is required after licence removal.
P8 End-User Rollout Easy, safe access for staff
  • Hide the Sync button on large libraries (ExcludeFromOfflineClient = $true) to prevent full-library syncs. Do not auto-mount libraries over ~5,000 items.
  • Roll out Add shortcut to OneDrive via a short staff guide — files-on-demand, per-folder. This is the recommended access method for end users.
  • Run a short walkthrough with super users / key contacts at the site before marking rollout complete.
P9 Decommission & Cleanup Close out securely
  • Reconcile once more (final count check); obtain written customer sign-off before decommissioning the source.
  • Retire the source file server per agreed procedure.
  • Remove any redundant or empty SharePoint libraries created during target preparation.
Delete any interim cloud staging (e.g. abandoned blob storage, staging containers) to remove the copied data and any live access keys. Leaving staging in place is a standing security and cost liability.

Tooling notes
Module requirements and known dependency locations
  • PnP.PowerShell requires PowerShell 7. Register an Entra app with the appropriate SharePoint and Graph permissions for interactive login.
  • Microsoft Graph licence cmdlets live in Microsoft.Graph.Users.Actions; directory and SKU cmdlets live in Microsoft.Graph.Identity.DirectoryManagement.
  • Always run destructive scripts in preview / WhatIf mode first and review the output before committing.
  • Security group propagation in SharePoint can take 15–60 minutes — do not test access immediately after group creation.
Migration Manager agent tip: Install the agent directly on the file server and exclude the source drive from antivirus. Session-tied migration tools (RoboCopy over RDP, etc.) will fail if the session drops — Migration Manager is cloud-orchestrated and survives disconnection.
Security group naming convention
Standard pattern for all SharePoint folder-level groups
SP_<FOLDER>_RWEdit permission — read, write, create, delete. Maps to NTFS Modify.
SP_<FOLDER>_RORead permission — read-only. Maps to NTFS Read.
SP_<FOLDER>_VERIFYView-only customer verification group — added before go-live; removed after sign-off if not ongoing.
Permissions are applied at folder level by breaking inheritance via Set-PnPListItemPermission using the SharePoint list-item ID of the folder — not by display name or URL.

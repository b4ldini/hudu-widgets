How the access model works
One rule covers everything — group membership = access

Each top-level folder is controlled by two Entra security groups. Permissions are set per folder (inheritance is broken at folder level), so adding someone to a group is the only thing that grants access. There is no direct sharing, no site-level role assignment.

SP_<FOLDER>_RW   →   Edit (read / write / delete)
SP_<FOLDER>_RO   →   Read-only (view / open only)
  • SP_ prefix marks it as a SharePoint folder-access group.
  • <FOLDER> is the folder name in CAPITALS with no spaces or punctuation (e.g. VOLADMIN not VolAdministrations).
  • _RW = add, edit, delete files.  _RO = view and open only.
  • Users must hold a SharePoint licence before group membership will grant access.
Site settings — do not change
Two settings are off by design; reversing either breaks access
Do not re-enable the "Limited-access user permission lockdown mode" site feature — it is OFF by design. This feature is required to be off for folder-level sharing to work. Turning it back on will break all folder-group permissions.
The library Sync button is hidden (ExcludeFromOfflineClient = $true). Staff access files via Add shortcut to OneDrive — do not re-enable the Sync button or auto-mount the full library.

How to assign folder access
Three steps — takes under a minute
1 Go to Entra admin centre (entra.microsoft.com) → Groups → search for the group, e.g. SP_HR_RW, and open it.
2 Members → Add members → search for the person by display name → Add. Confirm they hold a SharePoint licence first.
3 Access applies within a few minutes. They reach the folder via the SharePoint site URL or their OneDrive shortcut. For a new shortcut, share the Add shortcut to OneDrive staff guide.
New Entra security groups take 15–60 minutes to become usable in SharePoint after creation (replication delay). This does not apply to adding members to existing groups, which is near-instant.

Gotchas
Known quirks to be aware of before troubleshooting
  • New Entra security groups take ~15–60 minutes to become usable in SharePoint after creation — this is a replication delay, not an error.
  • Folder permissions are granted by list-item ID (via Set-PnPListItemPermission), not by folder display name. Renaming a folder does not break permissions.
  • SharePoint rejects the reserved folder name "Forms" and filenames containing emoji — these must be renamed at source; the invalid-character replacement setting does not cover them.
  • PnP.PowerShell requires PowerShell 7. Graph licence cmdlets are in Microsoft.Graph.Users.Actions; directory and SKU cmdlets are in Microsoft.Graph.Identity.DirectoryManagement.
Tenant is cloud-only. There is no AD sync. When looking up a user in Entra or running scripts, always match by display name — usernames and UPNs are not consistent with the on-prem AD accounts that were used on the file server.

MSP-NET-001 · Network Configuration

When a Draytek router is installed behind a third-party ISP router (BT or Virgin Media), the ISP router performs NAT. This means the Draytek receives a private IP address on its WAN port rather than the public IP — breaking inbound traffic and VPN tunnels.

The fix is a two-step process: assign the Draytek a fixed (reserved) IP on the ISP router's LAN, then point DMZ at that reserved IP. This forwards all unsolicited inbound traffic from the internet directly to the Draytek, which then applies its own firewall rules.

Section C · Verification
Confirming the DMZ is Working
1
 Confirm the Draytek WAN IP matches the reservation Log into the Draytek admin panel. Go to System Status or WAN Status. The WAN IP shown should match the reserved IP you set in the ISP router (192.168.1.10 for BT, 192.168.100.10 for Virgin Media).
✓ Good sign If the WAN IP on the Draytek matches exactly, the DHCP reservation is working.
2
 Check the Draytek's WAN gateway Still in Draytek WAN Status, the Gateway IP should be the ISP router's address — 192.168.1.254 (BT) or 192.168.100.1 (Virgin Media). If it is blank or wrong, release and renew the WAN DHCP lease.
3
 Test an inbound port from outside the network Use a mobile phone on 4G/5G (not connected to the Wi-Fi) or a remote tool like Port Scanner to probe a port that the Draytek should be listening on (e.g. HTTPS 443, or the SSL VPN port). It should show as open if the Draytek's firewall permits it.
4
 Test VPN connectivity (if applicable) If the site uses an IPsec or SSL VPN on the Draytek, attempt to connect from an external location. A successful tunnel handshake confirms DMZ is passing traffic correctly.
Troubleshooting reference
Symptom Likely cause Fix
Draytek WAN IP is still a random DHCP address Reservation not saved, or Draytek not yet rebooted Re-save reservation; release & renew WAN DHCP on Draytek
Inbound ports still blocked after DMZ enabled Draytek firewall blocking the port Check Draytek Firewall → Filter Rules; add an allow rule for the port
DMZ field missing in ISP router UI ISP router in modem-only / bridge mode already No DMZ needed — Draytek will receive the public IP directly; verify WAN IP is public
BT Hub shows "DMZ not available" Hub in modem mode or advanced features restricted by BT Check BT account for "Extra" tier; or contact BT business support
Virgin Media Hub 3 — DMZ option greyed out Hub not fully in router mode Confirm Firewall → Security Level is not set to "Custom high"; reset to medium, then enable DMZ
⚠ ISP Router in Modem-Only Mode If the ISP has placed the BT or Virgin Media hub into bridge / modem-only mode, the Draytek receives the public IP directly on its WAN port and double-NAT does not occur. In that scenario, no DHCP reservation or DMZ configuration is needed — the Draytek's own port-forwarding and firewall rules apply directly.
